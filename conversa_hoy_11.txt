● Build en proceso. Resumen técnico del bug y la solución:

  ---
  Causa raíz exacta

  El SDK de Firestore para Android, cuando .await() espera confirmación del
  servidor:
  - Con buena red: responde en 1-3 segundos ✓
  - Con red lenta o intermitente: puede tardar minutos o nunca responder ✗

  El flujo anterior era:
  click "Generar Factura"
    → isCreating = true
    → withTimeoutOrNull(8s) { getProfile() }   ← hasta 8 seg
    → withTimeout(12s)    { incrementCounter() } ← hasta 12 seg más
    → invoiceRepo.save()  ← SIN TIMEOUT → cuelga para siempre
    → onDone() nunca se llama → spinner infinito

  La factura SÍ se guardaba (Firestore escribe en caché local y sincroniza
  luego), pero el callback nunca llegaba porque .await() esperaba la
  confirmación del servidor.

  La solución

  Cada operación de escritura a Firestore ahora tiene su propio timeout de 5
  segundos. Si el timeout se activa, la escritura sigue corriendo en background
  (Firestore la sincroniza cuando haya red) pero el código continúa y llama a
  onDone inmediatamente.

  Flujo nuevo:
  click "Generar Factura"
    → withTimeoutOrNull(8s)  { getProfile() }     ← máx 8 seg
    → withTimeoutOrNull(2s)  { incrementCounter cache }
      ó withTimeoutOrNull(3s){ incrementCounter server }
    → withTimeout(4s) { escribir counter }        ← máx 4 seg
    → withTimeout(5s) { invoiceRepo.save() }      ← máx 5 seg
    → onDone() ← SIEMPRE se llama, máx ~17 seg total
